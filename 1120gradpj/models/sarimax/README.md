# SARIMAX 육지 SMP 72시간 예측

## 현재 상태

알고리즘과 시간순 평가 코드를 구현했다. 새 필수 입력 전체가 준비되지 않았으므로 실제 SMP 모델은 학습하지 않는다. 기존 달력 중심 실험으로 대체하지 않는다. `DATA_STATUS.md`, `data_status.json`, `source_inventory.json`에서 실제 차단 상태를 확인한다.

```sh
# 1120gradpj 폴더에서
.venv/bin/python models/sarimax/train.py --audit-only
.venv/bin/python models/sarimax/train.py
```

필수 데이터가 없으면 두 명령 모두 종료 코드 2를 반환한다. 학습 명령은 검사를 우회하지 않는다. 합성 시계열 테스트는 알고리즘의 기술 검증이며 SMP 성능 결과가 아니다.

## 알고리즘의 의미

SARIMAX(p,d,q)(P,D,Q,24)는 외부 요인의 효과를 설명하고 남은 SMP 흐름을 과거 가격·오차·하루 주기로 설명하는 모델이다.

`SMP_t = β × X_t + 시계열 잔차_t`

잔차에 대해 일반 ARIMA와 24시간 계절 ARIMA를 적용한다. p는 직전 잔차의 자기회귀 차수, d는 일반 차분 횟수, q는 과거 혁신 오차를 반영하는 차수다. P·D·Q는 같은 역할을 24시간 계절 간격에 적용한다. 통상 '과거 가격'이라고 설명하지만 외부 회귀를 뺀 잔차 구조라는 점을 구분한다. X에는 합의된 수요·공급·연료·기상·달력 입력을 넣는다. 이번 후보는 계절 차분 D=0이며 일반 차분 d=0/1을 비교한다.

예: 수요·날씨로 설명되지 않는 가격 패턴이 어제 같은 시간과 비슷하게 이어지는지를 학습한다. β는 다른 입력과 시계열 구조를 함께 고려한 통계적 연관이며 인과효과로 해석하지 않는다.

## 구현 파일

- `algorithm.py`: 학습·72시간 예측·상태 갱신·저장/복원
- `contract.py`: 필수 출처·입력 열·기간·미래 시각 검사
- `fuel.py`: 지정 엑셀의 연료비단가/LNG/원/kWh만 추출
- `train.py`: 완비 검사 → 후보 학습 → 검증 선택 → 고정 모델 최종 평가
- `../../configs/sarimax.json`: 기간·차수 후보·반복 상한

## 학습과 일별 예측

1. 2023~2024년 입력과 SMP로 계수와 ARIMA 파라미터를 추정한다.
2. 입력과 SMP의 평균·표준편차는 학습 구간에서만 구한다. 결과는 원/kWh로 역변환한다. 변수는 임의 삭제하지 않는다.
3. 세 후보 `(1,0,1)(1,0,0,24)`, `(2,0,1)(1,0,0,24)`, `(1,1,1)(1,0,0,24)`를 검증 MAE로 비교한다. 수렴 실패 후보는 실패로 기록한다.
4. 매일 23시까지 새로 관측된 자료만 `extend`로 필터링하여 상태를 갱신한다. 계수는 재추정하지 않는다.
5. 향후 72시간의 외생변수로 한 번에 예측한다. 발행 후 실제값은 이 예측 안에 넣지 않는다.
6. 검증으로 선택한 학습 종료 상태를 다시 불러와 2025년 하반기를 평가한다. 2025년 상반기의 실제값을 상태 업데이트에 쓰는 것은 6월 말 발행 시점에는 과거이므로 가능하지만, 계수 재학습에는 사용하지 않는다.

95% 구간은 statsmodels의 조건부 모형 구간이다. 미래 외생변수 자체의 불확실성이나 연료 가정의 오차를 포함하지 않으며 보정된 확률예측이라고 주장하지 않는다.

## LNG 파일 연결

사용자 지정 HOME 엑셀을 읽기 전용으로 검사한다. 다단 헤더에서 '연료비단가' → 'LNG' → '원/kWh'를 동시에 만족하는 열을 찾아 추출한다. 연료단가·열량단가로 바꾸지 않는다. 원본은 수정하지 않는다.

과거 평가에서는 대상월 LNG 단가를 사용한다. 월 경계가 있으면 해당 시간별 대상월을 따른다. 이것은 동월 LNG를 알고 있다는 조건부 실험이며 시점 인증 운영 평가가 아니다. 2026년 11월 시연용 매핑 함수는 2026년 10월 값으로 72시간을 고정한다. 열량단가 API와 국내 연료 2개월 지연 가정은 사용하지 않는다.

## 아직 필요한 공통 데이터

새 공통 데이터 폴더의 기본 위치는 공유 루트의 `SMP_SHARED_DATA/`다. `--shared-dir`로 변경할 수 있다. 기존 406열 부분 입력 데이터는 이 계약의 대체 자료가 아니다.

### manifest.json

`fuel_policy`는 configs/sarimax.json과 같아야 한다. `sources`에는 contract.py의 SOURCES 14개 ID별로 아래 항목이 있어야 한다.

```json
{
  "status": "complete",
  "evidence_file": "raw/실제원자료파일.csv",
  "unit": "실제 단위",
  "scope": "지역·포함 범위",
  "mapping": "원본 필드 → 입력 열 매핑",
  "availability_rule": "시차·예보 선택·FRED 기준일 규칙"
}
```

수집 증거 파일은 실제 존재해야 한다. 값이 없는 곳에 complete를 쓰면 안 된다. 원자료 정합성과 지연·추정 방법은 공동 데이터 준비 단계에서 검증하고 명세해야 한다.

### hourly.csv

2023-01-01 00시~2025-12-31 23시의 중복 없는 연속 시간축. 열은 `timestamp`, `smp`, `feature_origin`, `latest_nonfuel_source_timestamp`와 contract.py의 FEATURES 전체다. 각 시간의 학습 exog는 그 시간 이전의 명시된 feature_origin에서 만들 수 있는 입력이어야 한다. 해당 시점 이후의 관측을 끌어와 넣지 않는다. 국내 LNG만 명시적인 동월 제공 예외다.

### forecast_inputs.csv

`forecast_origin`, `target_timestamp`, `latest_nonfuel_source_timestamp`와 FEATURES 전체. 검증·평가의 각 공통 발행일마다 72행이 있어야 한다. 부족한 D+2/3 공식 예보는 과거 자료 기반 공통 추정 규칙으로 생성하고 방법을 명시한다. 필수 과거 예보 원본의 부재를 자체 추정으로 숨기지 않는다.

시각은 `+09:00` 또는 `Z` 등 시간대 오프셋을 포함한다. `latest_nonfuel_source_timestamp`는 LNG를 제외한 모든 과거 관측·예보 생성일·FRED 가용 기준의 최댓값으로 작성하며 발행시각을 넘으면 차단한다. 달력·대상시각 자체는 관측 시각에 포함하지 않는다. 이 메타데이터만으로 원본의 실제 공개시각까지 입증되는 것은 아니다.

필수 29개 입력 열 이름은 `contract.py`의 FEATURES를 기준으로 한다. `*_history`는 미래 실제값이 아니라 발행 전에 이용 가능한 과거값 또는 과거 통계다. `*_forecast`는 사전 예보나 명시된 인과적 추정값이다. 표준화 전에 의미·단위·집계 방식이 네 모델에서 같아야 한다.

## 출력과 검증

완비 후에만 artifacts/에 후보 상태·검증 탐색·예측 CSV·MAE/RMSE·일자별/월별 MAE를 저장한다. 모든 날짜 그래프를 자동 생성하지 않는다. 현재 그래프·R²·HTML 시각화 전체는 후속 평가 확장 대상이며, 데이터 차단 상태에서 최종 성과로 생성하지 않는다.

`tests/test_sarimax.py`는 합성 시계열로 72시간·시각·미래 실제값 차단·계수 고정 갱신·저장 복원·결측 차단·연료 월 경계를 검사한다. 합성 테스트 지표를 연구 결과로 제시하지 않는다.
