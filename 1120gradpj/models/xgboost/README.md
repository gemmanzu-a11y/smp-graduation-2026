# SMP 예측 XGBoost 구현·검증 설명

## 실행

1120gradpj 폴더 터미널에서:

```sh
.venv/bin/python models/xgboost/train_validated.py
```

기존 `train.py`는 과거의 고정 설정 비교 실험이다. 이번 `train_validated.py`는 검증 MAE로 설정과 트리 수를 선택하며 결과를 `artifacts_validated/`에 별도로 저장한다. 네트워크나 인증키 없이 이미 수집한 자료로 실행한다. LightGBM·LSTM 등 다른 모델 결과를 수정하지 않는다.

## 무엇을 예측하는가

매일 한국시간 23시에 다음 날 00시부터 3일 뒤 23시까지 육지 SMP 72개를 예측한다. 예를 들어 2025-07-01 23시 기준으로 7월 2~4일을 예측한다. 단위는 원/kWh다.

하나의 XGBoost 회귀모델을 사용한다. 같은 발행 시점의 과거 입력을 72개 행으로 복제하고 각 행에 대상 시간과 D+1/2/3를 붙인다. 출력은 행마다 SMP 숫자 하나다. 앞 시간의 예측을 다음 시간 입력에 넣는 재귀 예측은 아니다. 72개 모델을 학습하는 것도 아니다. 동일한 함수 f(과거정보, 대상시각, 예측거리)를 72번 평가한다.

## 실제 입력 데이터

기본 변수 8개 × 과거 48시간 = 384개 역사 특성에 달력·가격 기준값·결측률 등의 문맥 특성을 붙인다. 원본 406개 특성 중 학습기간 전체가 결측인 열을 제거한다. 제거 목록은 features.json에 저장한다. XGBoost는 남은 NaN의 분기 방향을 학습하므로 중앙값 대체나 표준화를 하지 않는다. 기존 공통 학습 코드의 전처리와 이 점이 다르다.

| 의미 | 실제 변수 | 사용 시점 |
|---|---|---|
| 가격 이력 | smp | 발행시점까지 48시간 |
| 전기 사용량 | demand_mw | 발행시점보다 24시간 앞에서 끝나는 48시간 |
| 공급 여유 | reserve_rate_pct | 같은 24시간 지연 |
| 태양광·풍력 실적 | solar_mwh, wind_mwh | 발행시점보다 48시간 앞에서 끝나는 48시간 |
| 관측 기온·일사·풍속 | temperature_c, solar_radiation_mj_m2, wind_ms | 24시간 지연 |
| 대상 날짜·시간 | horizon_days, target_hour, hour/dow/year sin·cos, is_weekend, is_holiday | 미리 아는 달력 |
| 비교할 가격 패턴 | origin_day_smp_same_hour, weekly_smp_same_hour | 발행일 같은 시각 가격, 대상시각 7일 전 가격 |
| 자료 품질 | 각 변수 history_missing_fraction | 입력 이력의 결측 비율 |

lagseq_000이 해당 변수의 가장 오래된 입력, lagseq_047이 가장 최근 입력이다. 변수별 지연이 다르므로 모든 변수의 lagseq_047이 같은 실제 시각은 아니다.

연료비 두 열은 과거 공개일을 증명하지 못해 현재 모두 결측으로 제외된다. FRED·기상예보·동서발전 태양광예보도 아직 이 데이터셋에 연결되지 않았다. 따라서 이번 모델을 수요·공급·연료·기상 전체를 완성한 모델이라고 부르면 안 된다. 공휴일은 기존 대체 달력이며 공식 API 수신본이 아니다. 수요의 육지 한정 범위도 아직 독립 검증되지 않았다.

24/48시간 지연은 보수적 가정이며 실제 공개 지연을 입증한 값은 아니다. SMP는 관측시각까지 사용하지만 그 시각의 실제 공개 여부도 별도 확인해야 한다. 과거 수정본과 발표 당시 원본이 같다는 보장이 없어 운영 성능 인증이 아닌 과거 재현 실험이다.

## 알고리즘: 틀린 부분을 나무가 순서대로 보완

회귀트리는 '과거 가격이 높은가?', '대상 시간이 낮인가?' 같은 조건으로 자료를 나누고 마지막 잎에 보정값을 저장한다. 처음에는 기본 예측값으로 시작하고 새 나무를 붙일 때마다 손실을 줄이는 방향으로 값을 고친다.

예측식: prediction(x) = base_score + learning_rate × Σ tree_m(x)

가령 초기 예측 100에 첫 나무 보정이 +10이면 학습률 0.045에서 100.45가 된다. 이후 나무는 이미 합쳐진 예측의 부족한 부분을 다시 보완한다. 단순히 실제 오차를 그대로 암기하는 대신, 손실의 1차 미분(gradient)과 2차 미분(Hessian)으로 분할과 잎 값을 결정한다.

학습 목적: 제곱오차 합 + 나무 복잡도 규제. 목적함수는 reg:squarederror이고 검증에서 모델을 고르는 기준은 MAE다. 학습 손실과 선택 지표가 다름을 구분한다. 이는 선형회귀의 변수별 계수를 구하는 방식과 다르며, 조건에 따라 수요·날씨 영향이 달라지는 비선형 관계를 학습할 수 있다.

## 설정의 뜻

| 설정 | 값 | 의미 |
|---|---|---|
| max_depth | 3, 5 비교 | 나무 조건의 최대 깊이. 깊을수록 복잡한 관계와 과적합 가능성 증가 |
| reg_lambda | 5, 15 비교 | 잎 보정값에 대한 L2 규제. 큰 보정을 억제 |
| learning_rate | 0.045 | 새 나무의 보정을 작게 반영 |
| n_estimators | 최대 1000 | 추가할 나무 수의 상한 |
| early_stopping_rounds | 50 | 검증 MAE가 50회 연속 개선되지 않으면 종료 |
| min_child_weight | 10 | 너무 적은 정보로 작은 잎을 만드는 것을 제한 |
| subsample | 0.9 | 나무마다 학습 행 일부 사용 |
| colsample_bytree | 0.85 | 나무마다 입력 열 일부 사용 |
| tree_method | hist | 값을 구간으로 나누어 분할 탐색을 빠르게 수행 |
| random_state | 42 | 재현을 위한 난수 시드 |

depth × lambda의 4개 조합을 비교한다. 각 조합에서 검증 MAE가 가장 좋았던 나무 수를 사용하고 그중 검증 MAE가 가장 낮은 조합을 고른다. scikit-learn 인터페이스의 predict는 조기종료 best_iteration을 반영한다. 학습 곡선은 선택된 후보의 train/validation MAE를 저장한다. 검증 결과가 개선되지 않거나 기준 모델보다 못해도 실패를 숨기지 않는다.

## 시간순 검증 절차

1. 학습 목표 시각: 2023~2024년. 초기 이력을 확보하느라 실제 첫 목표는 2023-01-10이다.
2. 검증 목표 시각: 2025-01-01~06-30. 설정과 나무 수 선택에만 사용한다.
3. 평가 목표 시각: 2025-07-01~12-31. 선택 완료 후 고정 모델로 예측한다.
4. 학습 720일×72행=51,840행, 검증 179일×72행=12,888행, 평가 182일×72행=13,104행이다. 72시간 블록이 기간 경계를 넘으면 전체 블록을 제외하므로 월수×매일과 정확히 같지 않다.
5. 동일한 실제 시각이 서로 다른 발행일·예측거리로 여러 번 평가될 수 있다. 이것은 발행일별 예측 평가다. 13,104행이 독립적인 실제 시간 13,104개라는 뜻은 아니다.
6. D+1/2/3 각각 MAE·RMSE·R², 월별 MAE, 시간대별 MAE를 저장한다.
7. 학습 이후 검증·평가 동안 재학습하지 않는다. 최신 운영용으로 전체 과거 자료에 다시 학습하는 단계와 구분한다.

무작위 train_test_split은 사용하지 않는다. test를 eval_set에 넣지 않는다. 미래 실제 기상·수요·발전량도 입력하지 않는다. 단, 기존 실험에서 2025년 하반기 결과를 이미 본 적 있으므로 완전히 처음 공개하는 외부 시험자료는 아니다. 이번 코드는 그 기간 오차를 기준으로 설정을 자동 선택하지 않는다. 이후 test 성능을 보면서 반복 튜닝하면 새로운 평가기간이 필요하다.

## 평가 숫자의 의미

MAE = 평균(|실제-예측|). MAE 10원/kWh이면 평균 절대 가격 오차가 10원/kWh라는 뜻이다. 정확도 90%라는 뜻은 아니다.

RMSE = sqrt(평균((실제-예측)^2)). 큰 오차에 더 큰 벌점을 주므로 가격 급등을 놓쳤을 때 커진다. R²는 평균값 예측 대비 설명력을 나타내며 음수도 가능하다.

기준 1: 발행일 00~23시 가격을 향후 각 날에 반복한다. 특히 D+2/3의 '전날 실제값'을 사용하지 않는다.
기준 2: 각 대상 시각의 7일 전 SMP를 사용한다. D+3까지 모두 발행시점 이전이다.

MAE 개선율 = 100 × (1 - 모델 MAE / 기준 MAE). 양수면 기준보다 좋고 음수면 나쁘다. 기준 예측이 더 좋으면 이번 모델의 개선 효과를 주장할 수 없다.

특성 중요도는 나무 분할의 gain 기반 상대값이다. 상관된 과거 변수끼리 중요도가 나뉠 수 있고, 인과효과나 '기온이 1도 올라 가격이 몇 원 상승'이라는 의미가 아니다.

## 이번 실제 실행 결과

검증 MAE로 선택한 설정은 max_depth=5, reg_lambda=15, 유효 트리 126개다. 검증 MAE는 9.4043원/kWh다. 원본 406개 중 386개를 사용했다. 제외된 20개는 전체 결측인 야간 일사 시차 열 18개와 연료비 열 2개다.

| 평가 범위 | XGBoost MAE | XGBoost RMSE | 발행일 반복 MAE | 지난주 동일시간 MAE |
|---|---:|---:|---:|---:|
| D+1 | 14.0173 | 17.6107 | 10.6931 | 11.3917 |
| D+2 | 14.3993 | 18.0885 | 13.6324 | 11.4362 |
| D+3 | 14.7502 | 18.4818 | 14.2141 | 11.4722 |
| 전체 | 14.3889 | 18.0639 | 12.8465 | 11.4334 |

단위는 모두 원/kWh다. 전체 MAE는 지난주 동일시간 기준보다 약 25.85% 크다. 현재 모델이 기준 예측을 개선했다고 주장할 수 없다. 검증 MAE와 평가 MAE가 다른 원인은 계절별 분포·가격 변화·입력 범위 등을 별도로 분석해야 하며, 숫자만으로 특정 원인을 확정하지 않는다. 평가 결과를 본 뒤 같은 평가기간에 맞춰 반복 튜닝하지 않는다.

기존 시간누수·전처리 등 테스트 10개와 새 XGBoost 시간 검증 3개가 통과했다. 저장 모델을 다시 불러와 평가 13,104행 전체 예측이 CSV와 일치하는 것도 확인했다. 마지막 실행 기록 저장 중 NaN JSON 표기 오류는 코드에서 수정했고, 이번 기록은 재학습 없이 저장 모델·평가표에서 복구했다. 전체 학습 실행시간은 복구할 수 없어 run.json의 seconds를 null로 기록했다.
